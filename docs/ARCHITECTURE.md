# Архитектура Telegram AI Bot

## Data Flow (Поток данных)
```
Telegram
 ↓
Ingest (Прием сообщений)
 ↓
Storage (Сохранение в сыром виде в PostgreSQL)
 ↓
Memory (Асинхронные воркеры для чанков, суммаризации и топиков)
 ↓
Search (Генерация эмбеддингов, векторный и полнотекстовый поиск)
 ↓
Context Builder (Сбор релевантного контекста для LLM)
 ↓
LLM (Генерация ответа)
 ↓
Response (Отправка ответа в Telegram)
```

## Ключевые архитектурные решения

### 1. Почему PostgreSQL?
PostgreSQL является надежной и зрелой реляционной СУБД, идеально подходящей для хранения структуры данных нашего приложения: пользователей, чатов, сообщений, фактов и взаимосвязей. Поддержка JSONB и расширений делает её универсальной.

### 2. Зачем pgvector?
Вместо отдельной векторной базы данных (типа Pinecone или Milvus), мы используем расширение `pgvector` для PostgreSQL. Это позволяет хранить векторные эмбеддинги рядом с реляционными данными, что упрощает гибридный поиск (семантика + метаданные + полнотекст) и избавляет от необходимости синхронизации между разными базами данных.

### 3. Зачем Redis?
Redis используется для:
- Управления очередями фоновых задач (суммаризация, эмбеддинги)
- Кэширования часто запрашиваемых данных
- Rate limiting и защиты от спама
- Распределенных блокировок (locks)
- Временного контекста диалога

### 4. Отделение LLM от бизнес-логики
LLM-провайдер скрыт за интерфейсом абстракции (LLMProvider). Это позволяет в будущем переключаться с Gemini на OpenAI, Anthropic или локальные модели без необходимости переписывать ядро бота. 

### 5. Многоуровневая память
- **Level 1 (Raw)**: Сырые сообщения Telegram (ID, текст, время, пользователь).
- **Level 2 (Summaries)**: Сжатые выжимки длинных дискуссий.
- **Level 3 (Topics)**: Тематические кластеры сообщений.
- **Level 4 (Structured)**: Извлеченные факты, решения, события, задачи с привязкой к источнику (provenance).
- **Level 5 (Personal)**: Память о конкретном пользователе.
- **Level 6 (Embeddings)**: Векторные представления для семантического поиска.

### 6. Асинхронная обработка и масштабирование
Бот не блокирует обработку сообщений запросами к LLM для суммаризации или извлечения фактов. Эти задачи ставятся в очередь и обрабатываются фоновыми воркерами. Архитектура построена с учетом мульти-тенантности, где каждый чат (Chat) имеет изолированный контекст.
